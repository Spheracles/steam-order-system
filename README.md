# 蒸汽式智慧訂單管理系統 v14.0

> **線上使用：** https://spheracles.github.io/steam-order-system/ （GitHub Pages）。網頁只有程式，不含任何訂單、日報、出貨或客戶資料；匯入的檔案只在使用者自己的瀏覽器處理，不會上傳。


**v14.0 主機操作改善**
- 主機狀態列往上移，並疊在鍋爐煙囪上方：「READY 待命」不再被擋住（1920／1440／1100／390px 皆以「最上層元素」逐點檢查）。
- 「執行查詢」按鈕與主啟動桿功能重複 → 改為「↺ 叫回上一筆」（按一次叫回最近的指令、再按叫回更早的，只叫回、不執行）；執行一律拉下主啟動桿（或按 Enter，保留鍵盤操作）。按鍵區另放「輸入切換」裝置與「清除輸入」，並寫明執行方式。
- 打字機按鍵可實際輸入：大千式四排 41 鍵＋大寫、空白、退格。注音模式按鍵先組字，列出內建「查詢常用詞」候選（例如 ㄉㄧㄥˋㄉㄢ → 訂單、訂單編號），點選或按空白插入游標位置；也可「直接輸入注音」。內建詞庫只含查詢常用詞（日期、出貨狀態、訂單、客戶、產品、排行、比較…），其他中文請用電腦本身的輸入法。
- 「輸入切換」裝置（黃銅旋鈕）切換為英文文書輸入：按鍵以由左而右的翻牌轉場換成 1～0、Q～P、A～;、Z～/（與大千式同一位置），預設大寫、可切換小寫；動態效果「最少」時直接換字。實體鍵盤打字時，打字機同一位置的鍵會跟著按下。輸入模式會記住。
- 機械印刷機跟著捲動：寬螢幕（≥1200px）時印刷機停在導覽列下方，捲動主機區時一路看得到印刷動畫；捲出主機區就跟著離開、不擋下方表格。印刷機不在畫面上（例如手機版）時，畫面上方浮出小印刷機播放印刷動作，印好後顯示結果單編號，可一鍵捲回結果單；點其他地方或 5 秒後自動收起。
- 修改前已備份 v13.0（`backups/v13.0_*`）。


**v13.0 每日趨勢圖（多檔彙整 ④）**
- 依彙整後計入的日報列，先按日期加總完成量與不良量、算出各日不良率（＝當日不良量 ÷ 當日完成量，不是平均各列百分比），再畫圖：上圖「每日完成量」長條圖、下圖「每日不良率」折線圖，兩張圖日期對齊、各自一個縱軸（不使用雙縱軸）。
- 標示日期（月/日＋星期）、完成量單位（日報有「單位」欄就用它；沒有時寫明「單位未標示」，可自行填寫單位名稱，只用來標示，不改數字；多種單位時一次只畫一種、不相加）、不良率百分比、分母（當日完成量合計、計入筆數）與資料來源（檔名、工作表、匯入時間、排除的重複／衝突／錯誤列）。
- 找出異常來源：可切換「依產線比較」（每條產線一組長條、一條折線，有圖例與線尾名稱，可勾選要顯示的產線，顏色固定跟著產線），或點某一天／表格的「依產線拆開」看當天各產線的完成量、不良量、不良率、與該產線平常的差距，以及每筆回報的來源工作表／列號。
- 圖表下方自動列出「圖表可直接支持的觀察」（最高／最低、高於整體的日子、前後段比較、各產線不良率、最高那天主要來自哪條產線）與「仍需查證的問題」（沒有回報的日子、分母偏小、部分產線缺資料、衝突與錯誤未計入、原表不良率不一致、單位、不能說明原因、不代表因果），全部由目前資料即時計算。
- 換檔就更新：重新匯入日報、改勾選工作表或處理衝突後圖表自動重畫；網站檔案裡沒有任何寫死的範例數字。
- 可下載趨勢圖 PNG／SVG（白底，含標題、單位、分母與資料來源）、每日趨勢 CSV；彙整 Excel 另含「每日趨勢」「每日×產線」「趨勢觀察」工作表。
- 修改前已備份 v12.0（`backups/v12.0_*`）。


**v12.0 訂單與出貨交叉核對**
- 新增第 10 區「訂單與出貨交叉核對」：訂單告訴我們客戶訂了多少，出貨紀錄告訴我們已交多少。
- 出貨紀錄可從第 10 區自己的「選擇出貨紀錄檔」或最上面「資料匯入」選擇（.xlsx 或一次多選 CSV）；依工作表名稱（出貨紀錄、出貨明細、交貨、送貨、出庫…）與欄位（出貨編號＋訂單編號＋出貨數量）自動判斷，不會被當成訂單。同一份活頁簿若另有訂單、產品主檔、客戶主檔，會一併匯入。
- 以「訂單編號」比對（忽略前後空白、全半形、大小寫），**不靠資料列位置**；同一訂單有多個品項時再用產品編號區分。
- 出貨紀錄先依「出貨編號」去重：內容相同只計一次；同編號但內容不同列為衝突，預設不計入、可選擇採用哪一版。**不同出貨編號的分批出貨全部保留、各自計入**（例如 S001 出 100＋20 → 累計 120 → 全部出貨）。
- 每張訂單列出訂單數量、累計出貨、未出貨數量與出貨狀態（未出貨／部分出貨／全部出貨／出貨超量／單位不一致），可依狀態篩選、搜尋，點「出貨筆數」看每一筆出貨的來源檔案、工作表、原始列號。
- 異常清單保留：查不到訂單（不併入任何訂單）、出貨超量、單位不一致（訂單用「組」、出貨用「個」→ 不直接相減）、出貨編號重複或衝突、出貨編號空白、數量錯誤、已取消的訂單仍有出貨等。
- 輸出核對結果、出貨紀錄明細、異常清單（CSV 或一個 Excel）。出貨紀錄保存在這個瀏覽器；訂單改版重新匯入時自動重新核對。
- 修改前已備份 v11.0（`backups/v11.0_*`）。


**v11.0 多檔彙整（生產日報）**
- 新增第 9 區「多檔彙整（生產日報）」。仍從同一個「資料匯入」入口選檔：活頁簿裡有「回報編號、日期、產線、完成量、不良量」的工作表（例如 `Day2_練習資料.xlsx` 的「做法4_基本_日報一」「做法4_基本_日報二」），或一次多選幾個日報 CSV，會自動送到這裡；訂單、產品、客戶資料不受影響。
- ① 先列出讀到的每個工作表與欄位、欄位對應結果與「可合併／缺少什麼」，再給出整體結論（欄名不同但視為同一欄、只在部分工作表出現的欄位都會列出）。可合併的工作表超過兩個時不自動猜，請勾選或按「只勾選這一組」。欄名認不出來時可在「調整欄位」手動指定。
- ② 以回報編號辨識重複（忽略前後空白、全半形、大小寫）：內容完全相同只計一次；同編號但內容不同列為衝突，標出不同的欄位，**預設都不計入**，由使用者選擇採用哪一版。
- ③ 依「日期＋產線」加總完成量與不良量，每組都列出來源工作表與筆數；④ 不良率＝不良量合計 ÷ 完成量合計，不直接平均各列百分比（畫面會同時顯示「若直接平均會得到多少」供對照，不採用）。
- ⑤ 輸出明細、彙總表、異常清單（各自的 CSV，或一個含「彙總表／明細／異常清單／說明」的 Excel）。空白、非數字、負數、不良量大於完成量的列不計入也不補值；原表的「合計」列自動略過。
- **追溯來源**：彙總表每組的「計入筆數」可點開，列出這組每一筆回報的來源檔案、工作表、原始列號（＝Excel 左側列號，CSV 為第幾行），並核對加總是否與彙總表相符；同日期、同產線但未計入的列（重複、衝突、錯誤）以灰色列出並說明原因。明細表也加上來源檔案欄。
- **多檔彙整自己的匯入入口（依使用者要求新增）**：第 9 區有「選擇日報檔」（可選一個 .xlsx，或一次多選 CSV，也可拖曳），判斷規則與上方「資料匯入」相同：依工作表名稱或欄位自動判斷，生產日報留在這裡彙整，訂單／產品主檔／客戶主檔照常匯入到第 1 區；結果與錯誤訊息顯示在這個入口下方。全頁因此有兩個匯入入口（v10 原本只有一個）。
- 彙整資料同樣只在瀏覽器處理並保存在這個瀏覽器；「清除彙整資料」或上方「清除資料」都會刪除。
- 順帶修正：Excel 中「有日期格式但沒有值」的空白格原本會讀成 1899/12/30（訂單交期也受影響），現在一律視為空白；匯入提示框偶爾多出的「null」字樣已移除。
- 修改前已備份 v10.0（`backups/v10.0_*`）。


**v10.0 單一匯入入口（升級重點）**
- 畫面上只剩一個匯入入口：選一個公司資料 Excel 活頁簿（例如 `Day2_公司資料.xlsx`，含訂單、產品主檔、客戶主檔三個工作表），或一次多選三個 CSV。系統依工作表名稱／檔名，或欄位內容，自動判斷每張表是訂單、產品主檔還是客戶主檔；檔名是 a.csv、b.csv 這種沒有提示的名稱也能靠欄位判斷。同一個入口也接受 PDF（每份一張表，可一次選三份）與 JSON 備份。
- 缺少必要的工作表或欄位時，明確列出缺什麼（例如「缺少產品主檔」「訂單缺少必要欄位：訂購數量（可用欄名例如：數量…）」），這次匯入整批不套用，畫面維持原本的資料，不顯示空白結果，也不自行補值。
- 交期統一顯示為 `YYYY/MM/DD HH:mm`（台灣時間）：Excel 日期時間儲存格、文字日期都會正確轉換，不會出現 46335.5 這種序號，也不會差 8 小時（已在台灣時區與美國時區各測一次）。原始資料沒有時間時以當天 00:00 顯示，滑鼠移到格子上會說明。
- 數量一律轉成數字（Excel 裡存成文字的數量也一樣）；**不同單位分開統計**：單位取自訂單的「單位」欄，沒有時取產品主檔的「單位」，例如「110,560 個、28,250 組」，不會把個和組加在一起。
- 匯入後資料自動保存在使用者自己的瀏覽器（IndexedDB），重新整理不用重傳；畫面顯示來源檔名與匯入時間；「清除資料」會同時清掉畫面與瀏覽器裡保存的資料。無痕視窗或別人的瀏覽器看不到這份資料。
- 網站裡不再內建任何訂單、產品、客戶資料：「載入內建測試資料」按鈕、內嵌的測試資料、範本裡的範例列、範例句裡的人名都已移除。範例句改成固定的通用句子，加上依匯入資料即時產生的「用目前資料試試」。
- 修改前已備份 v9.3（原始碼、單檔版與部署包）；原有的查詢、篩選、排序、匯出、圖表、交叉分析、機械主機都保留。


v9.3 更名：系統名稱改為「蒸汽式智慧訂單管理系統」（英文 Steam-Powered Intelligent Order Management System），主機改名為「蒸汽式智慧訂單統整印刷機」（Steam-Powered Smart Order Consolidation Press）。頁首英文副標改用鍍銀立體的維多利亞古典襯線字（小型大寫），黃銅銘牌底色不變；主機標題的中英文字體造型不變。為了通過 Claude 的公開分享審查（只接受 JPEG／PNG／GIF／WebP 圖片），內嵌字型改用 JavaScript 從記憶體載入、網頁小圖示改為 PNG，網頁中不再有其他格式的內嵌媒體；外觀與功能不變。

**VI-OMS MARK VIII 蒸汽式智慧訂單演算印刷主機** · Vintage Industrial Intelligent Order Management System

一套在瀏覽器內執行的繁體中文訂單管理工具。匯入訂單、產品主檔、客戶主檔（CSV／XLSX／XLSM／PDF）後，可以用日常中文查詢訂單、統計產品銷量、做客戶與產品交叉分析，並匯出報表與完整備份。

v9.2 修正已知問題並補做測試：中文查詢新增「星期三」「下週一到週三」「這週末」與兩個期間的比較（「11 月和 10 月比較」「本週比上週成長多少」）；PDF 預覽按 Esc 取消時會正確釋放檔案並復位；手機版統計螢幕改成直式版面（最小字由 7.8px 放大到 13.5px）、主機儀表文字不再重疊、拉桿區重新排版；舊瀏覽器的推子備援版面；列印改為白底黑字並印出完整明細；高對比（強制色彩）模式下推子、按鈕、選單看得到。另外用 LibreOffice 24.2 實測匯出檔與 PDF 匯入，並以 20 萬筆資料實測效能。

v9.0 起首頁是一台「蒸汽演算主機」：輸入指令、拉下主啟動桿，鍋爐加壓、齒輪演算、活版印刷機吐出一張**用真實查詢結果印成的結果單**。機械只是資料處理狀態的表現：查詢永遠先由 JavaScript 真正算完，動畫才跟上；動畫可以整個關掉，功能完全不變。

- **單一檔案**：`index.html` 內含全部 HTML、CSS、JavaScript 與 Excel、PDF 解析元件（約 3.0MB），雙擊即可用 Chrome、Edge 開啟。

## 二、系統功能說明

### 0. VI-OMS MARK VIII 蒸汽主機（v9.0 新增）

**標題銘牌**：頁首「蒸汽式智慧訂單管理系統」是拉絲拋光的黃銅銘牌（斜向反光帶、細拉絲紋、雙線刻框、鉚釘），中文為深色刻印字；下方英文「Steam-Powered Intelligent Order Management System」是鍍銀立體字：字型為內嵌的「VIOMS Victorian」（Latin Modern Roman 10 Bold 裁切版，屬於 19 世紀 Modern 體的古典襯線字，約 13KB），以小型大寫排列，字身是銀色漸層，外圍有深鋼色描邊與向下三層的鋼色厚度，描邊對銘牌最亮處的對比 ≥ 4.5:1，所以在原本的黃銅底上仍看得清楚。主機標題「蒸汽式智慧訂單統整印刷機」是暗紅金屬底配立體亮金字，英文副標為全大寫刻字並加上金色飾線。兩者都使用內嵌的標題字型「VIOMS Title」（Noto Serif CJK TC Black 只取標題用到的字，約 22KB），所以 Windows、Mac、手機看到的字體一致，也不需要網路。經計算，金屬字每個漸層色對背景最差仍有 5.0:1、英文副標 6.2:1、頁首刻字 7.7:1。

**操作分工**：拉桿＝啟動，推子＝調整參數，旋鈕＝切換模式，打字機＝輸入指令，印刷機＝輸出結果，儀表與燈號＝顯示狀態。

**主啟動桿（PULL TO RUN）**
- 兩種用法：點一下；或按住往下拉，拉過紅色「觸發」線再放開。拉不到紅線會回彈、不執行，狀態列會說明。
- 拖曳中按 Esc 可取消；查詢進行中不會重複啟動；拖曳放開後瀏覽器補發的 click 不會再觸發一次。
- 支援滑鼠、觸控、觸控筆（Pointer Events＋指標擷取）；取得焦點後按 Enter 或空白鍵也能啟動。
- 拉桿、打字機的 Enter、「執行查詢」按鈕、範例按鈕、最近查詢按鈕全部走同一個查詢入口，結果完全一致。
- 沒有輸入文字時拉桿＝依目前的篩選條件重新計算並印出結果單。
- 狀態流程：待機 → 已就緒 → 啟動 → 演算 → 印刷 → 完成（或異常）→ 復位，完整動畫約 1.7 秒。主機下方的流程條同步顯示目前在哪一步。

**打字機控制台**：打字時只有紙帶、按鍵、小齒輪與拉桿輕微跳動，不會啟動整台機器；中文輸入法選字中（組字狀態）不觸發任何查詢。送出後「已辨識」列顯示系統理解的條件，例如「客戶＝王小姐｜產品＝耳環｜月份＝2026/11（預備出貨日期）」；無法辨識或資料中找不到的部分用黃字標出。

**精密參數控制臺（7 支推子）**：每支都有上下限標示、即時數值、可直接輸入的數值窗、鍵盤方向鍵、觸控拖曳與螢幕閱讀器說明（aria-valuetext）。拖曳時只更新推子本身，放開（或停止 0.3 秒）後才重算，不會在拖曳中重建畫面。

| 推子 | 作用 |
|---|---|
| MIN QTY／MAX QTY | 訂購數量下限／上限（最底／最頂＝不限）。下限大於上限時自動調整另一支並顯示提示；與「搜尋篩選」的數量欄位雙向同步。 |
| TOP RANK | 排行與圖表顯示 TOP 5／10／20／ALL，與「顯示範圍」按鈕同步。 |
| DATE WINDOW | 以「基準日」（保留原生日期選擇器）為中心的 1／3／7／14／30 天區間，套用到目前選定的日期欄位；改用其他日期條件時自動回到「關閉」。 |
| THRESHOLD | 分析門檻：只在排行與圖表顯示達到門檻的產品，可選「最低數值」或「最低占比（%）」。圓餅圖把低於門檻者合併為「低於門檻 N 項」，百分比仍以全部數量計算；統計卡片、總數與訂單明細不受影響，畫面會說明隱藏了幾項。 |
| STEAM FX | 蒸汽特效 OFF／LOW／MED／HIGH，只影響畫面。 |
| SFX LEVEL | 合成音效音量（Web Audio，即時合成，沒有音檔）。**預設靜音**，調高之前不會建立任何音訊。 |

**結果單**：內容全部取自剛完成的查詢——指令、符合訂單筆數、總訂購數量、已出貨／未出貨、熱門商品（依目前統計指標，套用分析門檻）、套用條件、報表時間；結果很多時只印摘要。失敗時印紅色印章並寫出原因：「尚未匯入訂單資料」「指令辨識失敗」「客戶名稱欄位未設定」（依缺少的欄位）「日期格式無法辨識」等，失敗時畫面條件不會改變。匯出檔案時也會印一張「已輸出」單（含檔名）。

**分析模式旋鈕（ANALYSIS MODE）**：旋鈕在 BAR／PIE 之間轉動；舊圖收合、新圖展開，切換當下資料已更新完成，篩選條件不變。長條圖是黃銅柱，數值變化時從舊高度平滑伸縮；圓餅圖是旋轉進場的黃銅刻度盤；沒有正數資料時顯示空白狀態說明。

**版面**：寬度 1200px 以上時，印刷機在右側從上到下貫穿，控制台分兩列（打字機＋查詢引擎、推子＋分析工作站）；較窄時印刷機移到控制台下方。

**動態模式**（右上角）：完整／精簡（只有燈號、拉桿與結果單淡入，飛輪不轉）／最少（全部即時，沒有任何動畫）。作業系統開啟「減少動態效果」時預設為精簡；選擇會記在這台瀏覽器。主機捲出畫面或切到其他分頁時自動暫停動畫。

**手機**：不縮小整台機器，改為簡化主機頭（壓力錶、爐火、飛輪、齒輪）＋流程條、清楚的輸入區、可觸控拉動的拉桿、預設收合的推子面板（點標題展開）、直排卡片與可左右捲動的表格。

### 1. 智慧對話式查詢控制台（主機下方的打字機）
- 直接輸入中文，例如「查詢（客戶名稱）2026 年 11 月預備出貨的（產品名稱）訂單」或直接輸入訂單編號，按 Enter 執行（Shift＋Enter 換行）。以下句型中的「王小姐」「耳環」等是測試資料裡的虛構名稱，請換成你資料裡的客戶與產品。
- 會辨識：客戶名稱（可部分）、客戶編號、產品名稱／分類（可部分）、料號、訂單編號、年份、月份、日期、日期區間、今天／明天／本週／下週／本月／下個月／今年、民國年、出貨狀態、數量條件、排序、統計（排名、幾筆、幾件、買了什麼）、圖表切換。

- 句首加「再」「其中」「只看」會保留目前條件再加上新條件。
- 看不懂的句子會回覆「目前無法完整辨識這個查詢條件，請嘗試提供客戶名稱、產品名稱或日期。」並列出無法辨識的字詞，**不會猜測、不會改動畫面**。資料中沒有的客戶會明確說「找不到」。

### 3. 資料匯入（v10.0 改為單一入口）
- 只有一個匯入入口（可點選或拖曳）：一個 `.xlsx`／`.xlsm` 活頁簿，或一次多選三個 CSV；也接受 PDF 與 JSON 備份。
- **自動判斷資料類型**：先看工作表名稱或檔名（含「訂單」「產品／商品」「客戶／顧客」），再看欄位（訂單編號、數量、交期…；產品編號、產品名稱；客戶編號、客戶名稱）。名稱與欄位都符合的分數最高，每張表只會被用一次；沒用到的表（例如「說明」）會列出，隱藏工作表會略過。
- **三種資料都必要**：訂單、產品主檔、客戶主檔都要有，而且各自要有必要欄位——訂單：訂單編號、數量、交期、產品（料號或名稱）、客戶（編號或名稱）；產品主檔：產品編號、產品名稱；客戶主檔：客戶編號、客戶名稱。少任何一項就列出缺什麼，整批不套用。
- 下方三張卡片顯示系統判斷的結果；判斷錯了可以在卡片上改用其他工作表、改標題所在列或 CSV 編碼。
- CSV：自動偵測 UTF-8／Big5，可手動切換；自動偵測逗號、Tab、分號。
- XLSX／XLSM：讀取全部工作表並自動選出最符合的工作表（可手動切換，隱藏工作表會標示）；**XLSM 只讀資料，不執行巨集**；自動判斷標題列，也可手動指定；辨識 Excel 日期格式；料號以「00000」等格式儲存時保留前導零。
- 重複欄名、空白欄名會提示並自動改名；原始資料完整保留，不會覆蓋。
- 舊版 `.xls` 不支援，會提示「另存為 .xlsx 或 CSV」。

### 3-2. 多檔彙整（生產日報，v11.0 新增）
- 入口：上方「資料匯入」。判斷為日報的條件：有完成量或不良量欄，且「回報編號、日期、產線、完成量、不良量」至少認得 3 個（工作表名稱含「日報／報工／生產」時 2 個即可）。
- 可辨識的欄名（節錄）：回報編號／回報單號／報工單號；日期／生產日期／報工日期；產線／生產線／線別；完成量／完成數量／生產數量／產量；不良量／不良數／不良品數；不良率（選用，只用來比對）。
- 重複與衝突比對的內容：日期、產線、完成量、不良量、原表不良率，以及所有勾選工作表都有的其他欄位（例如品項）。
- 異常清單：回報編號空白、日期空白或無法辨識、產線空白、完成量／不良量空白或不是數字、負數、不良量大於完成量（以上未計入）；原表不良率與計算不一致、重複回報、合計列（提醒）；衝突（依選擇計入或不計入）。

### 3-1. PDF 匯入（v8.1 新增）
- 單一匯入入口可以選 `.pdf`（每份 PDF 是一張表；可一次選訂單、產品主檔、客戶主檔三份 PDF，或 PDF 和 CSV 混選）。每份 PDF 依序開啟擷取畫面，全部確認後才一起判斷類型並套用。
- 選檔後開啟擷取畫面：
  1. **選擇頁碼**：留白代表全部，或輸入「1-3,5」，按「重新擷取」。
  2. **自動整理**：可勾選「略過只有一格的列」（報表標題、頁首、頁尾頁碼）與「移除各頁重複的標題列」。
  3. **編輯擷取內容**：每列一行、欄位以 Tab 分隔；可直接修改、刪除列，或從 Excel 複製貼上。在編輯框內按 Tab 會插入欄位分隔。
  4. **確認標題列**：系統會自動判斷，也可以手動改；下方預覽即時顯示前 8 筆，並提醒欄數和標題不一致的列。
  5. 按「載入系統」，之後的欄位對應、對照、統計都和 Excel／CSV 相同。
- 載入後可按該資料卡片上的「編輯 PDF 擷取內容」回到擷取畫面修改。
- 系統依文字在頁面上的位置重建表格；料號、客戶編號以文字保存，前導零不會遺失。
- 部分 PDF（例如以 Noto／思源字型輸出的檔案）會把「小、手、耳、金、日」等字記成外觀相同的「康熙部首」字元，造成名稱對不上；系統擷取時會自動轉回標準中文字。
- 內建繁體、簡體中文字型對照表（CMap），字型沒有內嵌的中文 PDF 也能擷取。
- 只讀取文字，不執行 PDF 裡的任何程式。有密碼、損壞的檔案會明確提示；**掃描圖片型 PDF 沒有文字可讀，系統不做 OCR**，會請你改用原始 Excel／CSV 或先轉成文字型 PDF。

### 4. 欄位對應
每個來源獨立對應。訂單 13 個欄位（訂單編號、客戶編號、客戶名稱、產品料號、產品名稱、訂購數量、單價、訂單金額、訂單建立日期、預備出貨日期、實際出貨日期、出貨狀態、備註）、產品主檔 8 個、客戶主檔 7 個。系統依同義詞自動推測（例如「客戶」「買方名稱」「Customer Name」都會對到客戶名稱），每個欄位都可手動改；缺少欄位時會說明影響哪些功能，但不會停用整個搜尋。變更後立即重算。

### 5. 主檔對照
- 料號、客戶編號一律以文字比對（保留前導零，忽略大小寫與全／半形）。
- 狀態：已對照、未找到料號／客戶、訂單料號／客戶編號空白、重複料號／重複客戶編號（主檔重複但內容相同）、**資料衝突**（同編號名稱不同，系統不會自行挑選一筆）。
- 訂單上的客戶名稱與主檔不同時標示「名稱不一致」，同時保留原始值。

### 6. 搜尋與篩選
客戶名稱、全欄位關鍵字、訂單編號、客戶編號、產品名稱（含料號與分類）、產品料號、產品分類、備註、數量範圍、出貨狀態、料號／客戶對照狀態、資料異常；部分符合／完全符合；同一欄可用「、」分隔多個值。
預備出貨日期／訂單日期／實際出貨日期都可查：今天、明天、星期幾（本週／上週／下週）、星期區間、週末、本週、上週、下週、本月、下個月、指定年份（可輸入民國年）、年月、年月日、起訖日期（含起訖日）、逾期未出貨、尚未填寫、日期格式異常。所有條件同時成立才列出。

**客戶名稱搜尋框修正**：只匯入訂單（沒有任何主檔）也能搜尋；輸入框永遠可以輸入；支援注音、倉頡等輸入法（組字中不搜尋，選字後才更新）；重算時不會重建輸入框，所以不會失去焦點；搜尋有 0.2 秒緩衝，數萬筆資料也流暢。

### 7. 訂單明細與排序
點欄位標題排序（再點一次反向），可還原原始順序。數字以數值排序、中文以臺灣中文排序、日期以實際日期排序（民國／西元混用也正確），空白與無效值固定排在最後。排序不影響搜尋條件。分頁每頁 50／100／200／500 筆；可顯示原始欄位；表格可左右捲動。

### 8. 產品銷量統計與排行榜
- 指標：訂購量、已出貨量、訂單筆數、訂單金額；範圍：前 5、前 10、前 20、全部（也可用 TOP RANK 推子）。可用 THRESHOLD 推子設定分析門檻。
- 同一料號跨訂單的數量自動加總（不是計算訂單筆數）。
- 排行表含名次、料號、分類、指標值、占比、訂購量、已出貨量、訂單筆數、退貨數量、對照狀態。
- 有金額資料時另有「金額占比前 5 名」與「高銷量低金額／高金額低銷量」分析（以中位數劃分，規則寫在畫面上）。

### 9. 圖表（SVG）
長條圖與圓餅圖以按鈕、旋鈕或中文指令切換，切換不會重置條件。長條圖：依數值由大到小、Y 軸刻度、數值標籤、滑鼠提示、點擊可只看該產品的訂單、產品多時可橫向捲動。圓餅圖：每個產品固定顏色（不因篩選改變）、名稱、數值、百分比、滑鼠或觸控提示，超出的產品合併為「其他」。手機上點一下看數值、再點一下才篩選。色盤已用色盲模擬驗證。

### 10. 客戶與產品交叉分析
客戶 × 產品（或產品分類）矩陣，可切換「依客戶看產品／依產品看客戶」、列排序、點欄位標題依該欄排序；含列合計、欄合計；格子顏色深淺代表數值；**點任一格會列出對應訂單明細**；點客戶或產品名稱可單獨篩選；可匯出完整矩陣 CSV。期間以「搜尋與篩選」的日期條件指定。

### 11. 資料檢查與異常清單
自動檢查：主檔重複料號、主檔料號衝突、主檔料號空白、客戶主檔重複編號／衝突／空白、空白訂單編號、無效日期（三種日期）、數量空白、非數字數量、數量為零、負數數量、訂單料號空白、未找到料號、未找到客戶、客戶編號空白、客戶名稱不一致、缺少客戶名稱、缺少產品名稱、出貨狀態無法判讀、金額／單價非數字。每項列出來源檔案的列號、原始值與說明，可點選類型只看該類訂單，可匯出 CSV。

### 12. 匯出與備份
- CSV（UTF-8 含 BOM，Excel 可直接開啟繁體中文）：全部訂單明細、目前搜尋結果、產品排行、客戶產品交叉統計、異常清單。正確處理逗號、雙引號、換行；以 `= + - @` 開頭的文字會加單引號，防止公式注入。
- XLSX：一次匯出「目前搜尋結果、產品排行、客戶產品交叉、異常清單、匯出說明」5 個工作表（標題粗體、凍結窗格）。
- **三檔合一 Excel（v8.1 新增）**：把訂單、產品主檔、客戶主檔各存成一張工作表（「訂單資料」「產品主檔」「客戶主檔」）；有產品或客戶主檔時，另附「完整對照結果」工作表（含對照狀態、轉換後的西元日期與全部原始欄位），最後是「說明」工作表（來源、筆數、對照統計）。
  - 以 0 開頭或含連字號的值（00123、0012、0912-000-001）一律存成「文字」儲存格並套用文字格式「@」，在 Excel 開啟、編輯後都會保留前導零；一般數字仍存成數值，可直接加總。
  - 這個檔案可以直接從匯入入口匯回本系統，會自動選對三張工作表（不會誤用「完整對照結果」）。
- JSON 完整備份：三份原始資料、欄位對應、搜尋條件、排序、圖表類型、統計指標、查詢紀錄，以及 v9.0 新增的**控制臺設定**（推子、分析門檻、日期窗與基準日、蒸汽特效、音量、動態模式），格式版本號 v9。還原時先顯示摘要，提醒會覆蓋目前資料，確認後才套用，並把推子恢復到備份當時的位置；可讀取 v8 與 v2.0～v7.0 舊版備份（舊版沒有的控制臺設定採預設值）。若作業系統要求減少動態效果，還原不會把動畫打開成「完整」。
- **備份檔含有客戶名稱等個資**，請妥善保存，不要上傳到公開位置。
- 還原備份：在「資料匯入」只選那一個 JSON 檔，先顯示摘要，確認後才覆蓋。
- **瀏覽器保存（v10.0 起自動）**：匯入後資料自動保存在這個瀏覽器（IndexedDB），重新整理或下次開啟自動載入；資料與畫面設定分開存，只有資料變動時才重寫整份資料。共用電腦用完請按「清除資料」。

## 三、統計規則（統計口徑）

| 項目 | 規則 |
|---|---|
| 訂購量 | 只加總「數量大於 0、且出貨狀態不是取消或退貨」的明細 |
| 已出貨量 | 上述明細中，出貨狀態為已出貨／已完成等，或狀態未填但有有效「實際出貨日期」者 |
| 未出貨量 | 上述明細中，狀態為未出貨／處理中等，或有實際出貨日期欄但未填 |
| 出貨狀態不明 | 沒有出貨資料或狀態無法判讀；不計入已出貨也不計入未出貨 |
| 數量為 0 | 不計入訂購量，列入異常清單 |
| 負數或狀態為退貨 | 列為「退貨／沖銷」另計，不扣抵、不計入排行 |
| 已取消 | 另計，不計入訂購量 |
| 數量空白或非數字 | 不計入，列入異常清單；系統不會把每筆訂單當作 1 件 |
| 預備出貨訂單數 | 有有效預備出貨日期、尚未出貨、且非取消／退貨的明細筆數 |
| 數量單位（v10.0） | 每筆明細的單位取自訂單的「單位」欄，沒有時取產品主檔的「單位」；不同單位的數量分開加總與顯示（例如 110,560 個、28,250 組）。排行與占比只在同一個單位內比較；圓餅圖與交叉表的「合計」在多種單位時會標示「僅供參考」。對不到產品主檔、也沒有單位的明細顯示為「（未標單位）」；整份資料都沒有單位時沿用「件」 |
| 金額 | 優先用「訂單金額」欄；沒有時用「單價 × 數量」，再沒有則用產品主檔單價估算（畫面會標示「估算」） |

沒有任何出貨資料時，系統只稱為「訂購量」，不會宣稱已完成實際銷售。

## 四、使用者操作教學

1. 用 Chrome 或 Edge 開啟 `index.html`（或打開公開網址）。
2. 在「資料匯入」按「選擇公司資料檔」：選一個含訂單、產品主檔、客戶主檔的 .xlsx，或一次多選三個 CSV。缺什麼系統會列出來。
3. 匯入後資料會保存在這個瀏覽器，重新整理不用重傳；用完（尤其是共用電腦）按「清除資料」。
4. 到「欄位對應」看每個欄位是否正確；黃字代表缺少欄位會影響的功能，不正確就從下拉選單改選。
5. 在主機下方的打字機輸入問題，按 Enter 或拉下右側主啟動桿；結果會印在右上方的結果單，下方表格與圖表同步更新。也可以到「搜尋與篩選」設定條件。
6. 想微調時用左側推子（數量上下限、排行數、日期窗、分析門檻），用「ANALYSIS MODE」旋鈕切換圖表。
7. 在「訂單明細」排序、翻頁；在「銷量統計」切換指標與圖表；在「客戶與產品交叉分析」點格子看明細。
8. 到「資料檢查與異常清單」處理錯誤資料（例如料號打錯、日期無法辨識）。
9. 要換電腦時，在「匯出與備份」下載 JSON 備份，在新電腦的「資料匯入」選這個 JSON 檔還原。

**Excel 小提醒**：料號、客戶編號請設為「文字」格式；若 Excel 已把 00123 存成數字 123，系統無法還原前導零。

## 六、尚未完成的功能與限制

- 不支援舊版 `.xls`（請另存為 `.xlsx` 或 CSV）。Excel 公式只讀取檔案內已儲存的計算結果，不會重新計算。
- PDF：只能擷取文字型 PDF，不做 OCR；表格是依文字位置推算，儲存格內自動換行、跨欄合併、旋轉文字或沒有對齊的版面，可能需要在擷取畫面手動修正。系統以「欄數最多的一列」當作欄位基準，若標題列比資料列少欄，請檢查預覽。
- 中文查詢是規則式解析：能處理上列句型；同時問兩個獨立問題、口語縮寫或錯字目前無法理解，會提示改寫。
- 期間比較只支援「兩個期間」互相比較；不能比較兩位客戶或兩項產品（「王小姐和陳先生比較」會說明目前只支援期間比較），也不能一次比較三個以上期間。兩個期間不相連時，下方表格與圖表只能顯示涵蓋兩期的連續範圍（含中間日期），比較數字則只算兩期本身。
- 一句話裡出現兩個日期但沒有說要比較時，只採用第一個，並在回覆中提醒。「每週一」這種週期性條件不支援。
- CSV 沒有欄位型別：用 Excel 或 LibreOffice 直接開啟 CSV 時，00123 這類前導零編號會被轉成數字 123（已用 LibreOffice 24.2 實測確認）。需要保留時請用 XLSX 匯出（編號存成文字），或在試算表的匯入對話框把編號欄設為文字。
- 列印：列印時一律改成白底黑字、隱藏主機動畫區、明細表完整列出（A4 橫向）。版面以「看得清楚」為主，沒有另外設計列印專用的排版；欄位很多時明細表的字較小、部分欄位會折行。
- 交叉矩陣畫面最多顯示 80 列 × 14 欄（其餘合併為「其他」），完整內容請匯出 CSV。
- XLSX 匯出為純資料表，不含圖表；圖表可截圖使用。
- 沒有多人共用、帳號權限或雲端同步（刻意設計：資料只留在各自的瀏覽器）。
- 瀏覽器保存使用 IndexedDB：清除瀏覽器資料時會消失，無痕視窗、別的瀏覽器或別台電腦看不到；部分隱私設定很嚴格的環境可能不允許保存，畫面會寫明「無法保存」，這時重新整理後要重新匯入。重要資料請另以 JSON 備份保存。
- 多檔彙整（v11.0）只處理日報格式（每列一筆回報）；JSON 完整備份不含彙整的日報（日報請保留原檔或匯出彙整 Excel）。彙總只依「日期＋產線」，沒有依品項或班別分組。
- v10.0 起三種資料都必須一起匯入，不再支援「只匯入訂單」；只想更新其中一份時，也要把三份一起選（或用同一個活頁簿）。
- 自動判斷資料類型依名稱與欄位；如果工作表與欄位名稱都和常見寫法差很多（例如全部是英文縮寫），系統會列出找不到哪一種資料，請改工作表名稱或欄名後再匯入。
- 多種單位時，「哪一種產品訂購量最高」會依單位分組回答；圓餅圖把不同單位放在同一個圓裡，只能看大略比例。
- 機械主機（v9.0）：
  - 垂直推子使用瀏覽器原生的滑桿加上 `writing-mode` 直排（Chrome／Edge 124、Safari 17.4、Firefox 120 以後支援）。v9.2 起，開啟時會先量測瀏覽器是否真的把滑桿直放，不支援時自動改用「橫向滑桿旋轉 90°」的備援版面，拖曳方向與數值相同。此備援只在新版 Chrome 中「強制啟用」測試過，沒有在真正的舊瀏覽器上測試；萬一仍顯示異常，推子下方的數值窗功能完全相同。
  - 壓力錶、溫度管、蒸汽量都是處理狀態的示意，不代表任何真實數值；需要數字請看結果單、統計卡片與統計分析儀。
  - 動畫以 SVG 屬性更新，在很舊的電腦上可能不夠流暢；請切換到「精簡」或「最少」，功能完全相同。
  - 同一個指令在動畫尚未結束（約 1.7 秒）前再按一次會被忽略（避免重複執行）；換成不同指令則立即執行並以最後一個為準。
  - 結果單收集匣只保留在目前頁面，重新整理後清空，也不會寫進備份（結果單內容都可從備份的資料與條件重新算出）。
  - 機台上的銘牌只保留中文（原本的小英文字在一般螢幕上小於 8 像素，讀不清楚，已移除）；壓力錶、溫度錶錶面字很小，所以主機下方另有一行文字說明它們只是示意。
  - 機台全部以程式繪製的 SVG 與 CSS 組成（沒有圖片檔，離線也能顯示），立體感來自漸層、亮暗邊與陰影，不是照片或手繪插畫等級的細節。參考圖中的人物、英國國徽與國旗、大笨鐘等真實地標刻意沒有放入；背景的遠方廠房是虛構剪影。
  - 機台細節較多，在很舊的電腦上捲動或動畫可能不夠流暢；請切換到「精簡」或「最少」。

## 七、網站部署說明

`index.html` 是純靜態檔案，任何能放 HTML 的 HTTPS 網站空間都能部署，不需要資料庫或伺服器程式。公開後每位訪客各自匯入自己的資料，彼此看不到，網站主人也看不到。

### A. GitHub Pages（免費）
1. 登入 GitHub，建立新的 repository（例如 `order-console`）。免費帳號請選 Public。
2. 按「Add file → Upload files」，上傳 `index.html`、`.nojekyll`、`README.md`、`THIRD_PARTY_LICENSES.txt`，按「Commit changes」。
3. 進入 repository 的 **Settings → Pages**，在「Build and deployment」的「Source」選 **Deploy from a branch**，Branch 選 `main`、資料夾選 `/(root)`，按 **Save**。
4. 等待數分鐘（GitHub 說明最長可能約 10 分鐘），同一頁面上方會出現「Visit site」，網址形式為 `https://你的帳號.github.io/order-console/`，預設即為 HTTPS。
5. GitHub Pages 不讀取 `_headers`；`index.html` 內已內建相同的 CSP（`<meta http-equiv="Content-Security-Policy">`），仍能阻擋對外連線。

### B. Cloudflare Pages（免費，支援 `_headers` 安全標頭）
1. 登入 Cloudflare 主控台，進入 **Workers & Pages**。
2. 選 **Create application**，再選拖放上傳（Drag and drop your files／Use direct upload，名稱依 Cloudflare 介面為準）。
3. 輸入專案名稱，把整個部署資料夾（或 zip 檔）拖進去，按 **Deploy site**。
4. 完成後網址形式為 `https://專案名稱.pages.dev`，`_headers` 會自動套用（CSP、禁止被其他網站嵌入、nosniff、no-referrer）。
5. 拖放上傳單檔上限 25 MiB；本系統約 2.9 MB。

### C. Claude 網頁（已發布）
- 發布到 Claude 網頁的是「公開分享版」（`tests/build.py` 產生的 `dist/hosted/`）：不在執行時載入字型檔，六個使用內嵌字型的標題改為事先用正式版截成的透明 PNG（`t/*.png`，依 1440／900／390 寬度各一張），圖示改為獨立的 `favicon.png`；文字仍保留給螢幕閱讀器，列印與高對比模式會改回顯示文字。另外移除 pdf.js 內建、本系統用不到的「字型載入測試用」OpenType 字型，並把中文 PDF 字型對照表（CMap）改放在獨立的 `cmaps.json`（數字陣列，匯入 PDF 需要時才從同一個網站讀取），網頁內不再有任何 base64 二進位資料。PDF 解析元件 pdf.js 也改為同網站的 `pdf.lib.js`、`pdf.worker.js`，第一次匯入 PDF 時才載入（以 5 個分享測試頁定位：網頁內嵌 pdf.js 時審查無法通過，拿掉後可以通過）。功能與單檔版相同。原因：Claude 公開分享審查只接受 JPEG／PNG／GIF／WebP 圖片與常見影音，網頁載入字型檔會出現「無法審查此版本」。
已在 Claude 發布為互動網頁，目前**只有你本人看得到**。要公開，請在 claude.ai 開啟該網頁，使用頁面上的分享功能設定公開範圍。在 Claude 網頁中下載檔案時，平台會先跳出確認視窗。

### 修改後重新部署的注意事項
`index.html` 內建的 CSP 以 SHA-256 雜湊鎖定三段程式碼（PDF 解析的背景程式另以 `worker-src blob:` 允許）；若你自行修改 `index.html` 的 JavaScript，雜湊會不符，瀏覽器會拒絕執行。請把 `<meta http-equiv="Content-Security-Policy" ...>` 這一行與 `_headers` 裡的 `Content-Security-Policy` 一起更新或移除。
